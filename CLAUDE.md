# Паспорт бота

## Название бота
Бот-консультант по базе знаний (или «БазаЗнанийBot»)

---

## Цель и задачи

**Цель:**
Обеспечить пользователям быстрый и круглосуточный доступ к информации из структурированной базы знаний и каталогу услуг без участия человека.

**Задачи:**
- Мгновенно отвечать на запросы пользователей на основе данных из базы (RAG + LLM).
- Показывать витрину услуг и сохранять корзину между сессиями.
- Снизить нагрузку на сотрудников, отвечающих на однотипные вопросы.
- Предоставлять актуальную информацию в удобном текстовом формате в Telegram.
- Фиксировать запросы, на которые нет ответа, для последующего дополнения базы.
- Помнить контекст диалога (включая действия по кнопкам) после перезапуска бота.

---

## Целевая аудитория
Клиенты и потенциальные заказчики, которым нужен оперативный доступ к справочной информации об исполнителе и услугах (портфолио, цены), а также сотрудники/владелец, управляющие содержимым базы.

---

## Функции для пользователя бота
- **Функция 1** — поиск информации по свободному тексту (ключевые слова, уточняющие вопросы).
  Потребность: быстро найти нужные данные, не открывая саму базу и не ожидая ответа оператора.
- **Функция 2** — витрина услуг и корзина.
  Потребность: посмотреть услуги с ценами, добавить в корзину; корзина сохраняется между сессиями (повторное добавление той же услуги не дублируется).
- **Функция 3** — постоянное меню и связь с человеком.
  Потребность: всегда доступны кнопки «Витрина», «Корзина», «Связаться с человеком»; запрос на связь уходит владельцу вместе с контактами.
- **Функция 4** — сообщение о том, что нужной информации нет, и автоматическое уведомление владельца.
  Потребность: понимать, что запрос зафиксирован, и он не останется без внимания.
- **Функция 5** — память диалога.
  Потребность: бот помнит последние реплики (вопросы, ответы, витрину, корзину) и после перезапуска; в контекст нейросети идут последние 20 сообщений.

---

## Функции для владельца бота
- **Функция 1** — уведомления о запросах, на которые не нашлось ответа в базе.
  Потребность: своевременно дополнять базу данных и улучшать качество консультаций.
- **Функция 2** — просмотр статистики популярных запросов (`/stats`).
  Потребность: анализировать, какая информация требуется чаще всего.
- **Функция 3** — управление содержимым базы через команды (`/add`, `/list`).
  Потребность: поддерживать актуальность данных без отдельной админки.
- **Функция 4** — уведомления о запросах «Связаться с человеком».
  Потребность: вовремя ответить клиенту лично.

## Сценарии использования

**Сценарий 1. Поиск по ключевому слову / вопрос**
Пользователь вводит текст → Бот ищет релевантные фрагменты в SQLite → Передаёт их в LLM (DeepSeek) вместе с историей диалога → Выдаёт короткий ответ. Свободный текст не перехватывается кнопками меню.

**Сценарий 2. Уточняющий вопрос и память диалога**
Пользователь получает ответ (или смотрит витрину / корзину) и задаёт уточнение («А какая цена?», «О чём мы говорили?») → Бот читает историю из SQLite → Отвечает с учётом контекста. Повторный `/start` историю и корзину не сбрасывает.

**Сценарий 3. Информация не найдена**
Пользователь задаёт вопрос → Нет данных ни в базе, ни в истории диалога → Бот сообщает, что ответа пока нет → Уведомляет владельца → Владелец дополняет базу.

**Сценарий 4. Витрина и корзина**
Пользователь нажимает «Витрина» → Карточки услуг из базы знаний (название, описание, цена) с кнопкой «Добавить в корзину» → Добавление сохраняется в SQLite → «Корзина» показывает список; повторное добавление той же услуги — «Уже в корзине».

**Сценарий 5. Связь с человеком**
Пользователь нажимает «Связаться с человеком» → Получает контакты из настроек → Владельцу уходит уведомление (если запрос не от него самого).

## Инструменты и интеграции
- **Telegram Bot API** (aiogram 3) — канал связи с пользователями.
- **SQLite** (`data/knowledge.db`, aiosqlite) — база знаний, пользователи, корзина, история диалога, заготовки заказов; файл в `.gitignore`.
- **Python 3.11+** — логика бота.
- **DeepSeek** (OpenAI-совместимый API) — RAG-ответы по фрагментам базы и истории диалога.
- **Сервер (VPS / Cloud)** — для круглосуточной работы.
- **Система логирования** — статистика запросов и отладка.

### Хранение в SQLite (кратко)
- `knowledge` — записи базы знаний (услуги/профиль и т.д.).
- `users` — кто и когда общался с ботом.
- `cart_items` — корзина (UNIQUE по пользователю и услуге).
- `dialog_messages` — история диалога (роли user/assistant).
- `orders` / `order_items` — заказы и статусы (под будущую оплату).
- `query_log` / `unanswered` — статистика и незакрытые вопросы.

Ключи и токены в базе не хранятся (только в `.env`).

## Ограничения и риски

**Ограничения:**
- Бот работает только с текстовыми запросами и кнопками (аудио, видео, изображения не обрабатываются).
- Ответы по фактам зависят от актуальности и полноты базы знаний.
- Оформление заказа и оплата пока не подключены (таблицы заказов подготовлены).
- Бот не выполняет внешние транзакции; корзина — накопление интереса к услугам.

**Риски:**
- Сбои в работе базы данных или сервера могут сделать бота временно недоступным.
- При нечётком запросе LLM может дать неточный ответ, если не сработают ограничения (guardrails).
- Риск утечки токена бота при публикации в открытых репозиториях.
- В SQLite есть персональные данные клиентов (telegram_id, имя, история) — файл не коммитить; соблюдать требования к защите данных.
