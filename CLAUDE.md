# Паспорт бота

## Название бота
Бот-консультант по базе знаний (или «БазаЗнанийBot»)

---

## Цель и задачи

**Цель:**
Обеспечить пользователям быстрый и круглосуточный доступ к информации из структурированной базы данных (или базы знаний) без участия человека.

**Задачи:**
- Мгновенно отвечать на запросы пользователей на основе данных из базы.
- Снизить нагрузку на сотрудников, отвечающих на однотипные вопросы.
- Предоставлять актуальную информацию в удобном текстовом формате.
- Фиксировать запросы, на которые нет ответа, для последующего дополнения базы.

---

## Целевая аудитория
Сотрудники компании, клиенты, партнёры или любые пользователи, которым необходим оперативный доступ к справочной, технической, нормативной или иной структурированной информации из закрытой или открытой базы данных.

---

## Функции для пользователя бота
- **Функция 1** — поиск информации по ключевым словам или номерам записей.
  Потребность: быстро найти нужные данные, не открывая саму базу и не ожидая ответа оператора.
- **Функция 2** — получение уточняющих ответов по конкретному объекту (например, статус заказа, характеристики товара, реквизиты документа).
  Потребность: получить не общий, а точный и персонализированный ответ из базы.
- **Функция 3** — сообщение о том, что нужной информации нет, и автоматическое уведомление владельца.
  Потребность: понимать, что запрос зафиксирован, и он не останется без внимания.

---

## Функции для владельца бота
- **Функция 1** — уведомления о запросах, на которые не нашлось ответа в базе.
  Потребность: своевременно дополнять базу данных и улучшать качество консультаций.
- **Функция 2** — просмотр статистики популярных запросов.
  Потребность: анализировать, какая информация требуется чаще всего, и оптимизировать структуру базы.
- **Функция 3** — управление содержимым базы (добавление/редактирование записей) через отдельный интерфейс или команды.
  Потребность: поддерживать актуальность данных без необходимости заходить в основную систему.

---

## Сценарии использования

**Сценарий 1. Поиск по ключевому слову**
Пользователь вводит запрос или номер объекта → Бот обращается к базе данных → Находит совпадение → Выдаёт краткую справку или полную информацию в зависимости от настроек.

**Сценарий 2. Уточняющий вопрос**
Пользователь получает первый ответ и задаёт уточняющий вопрос (например, «А какая цена?») → Бот понимает контекст (сохраняет историю диалога) → Делает дополнительный запрос к базе → Возвращает конкретное значение.

**Сценарий 3. Информация не найдена**
Пользователь задаёт вопрос → Бот не находит данных в базе → Бот сообщает, что ответа пока нет → Отправляет уведомление владельцу с текстом запроса → Владелец позже дополняет базу, после чего аналогичный запрос будет обработан успешно.

## Инструменты и интеграции
- **Telegram Bot API** — канал связи с пользователями.
- **PostgreSQL / MySQL / MongoDB** — хранение основной базы данных для консультаций.
- **Python + aiogram** — разработка логики бота.
- **DeepSeek или аналогичная LLM** — для обработки естественного языка, если запрос не является точным совпадением.
- **Сервер (VPS / Cloud)** — для круглосуточной работы.
- **Система логирования** — для сбора статистики и отладки.

---

## Ограничения и риски

**Ограничения:**
- Бот работает только с текстовыми запросами (аудио, видео, изображения не обрабатываются).
- Ответы полностью зависят от актуальности и полноты базы данных.
- Бот не принимает решения и не выполняет транзакции (например, не оформляет заказы), он только предоставляет информацию.

**Риски:**
- Сбои в работе базы данных или сервера могут сделать бота временно недоступным.
- При нечётком запросе LLM может дать неточный или обобщённый ответ, если не настроены ограничения.
- Риск утечки токена бота при публикации в открытых репозиториях.
- Если база содержит персональные данные, требуется соблюдение законодательства о защите данных.
